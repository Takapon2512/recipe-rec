## S-003 メール検証コード入力

**URL**: `/signup/verify`
**Figma**: [{TBD}]({TBD})

### 🎯 目的

- サインアップ直後のユーザーに、メール宛に送られた検証コードを入力してもらいアカウントを有効化する
- 6桁という短いコードでも、誤入力・期限切れ・メール未着といったよくあるつまずきにフォローを入れる
- 「メールが来ない」「コードが切れた」などのケースから、ユーザーが自力で前進できる導線を用意する

### 📋 構成要素

#### ヘッダー（上部固定、56px / 共通仕様準拠）

| パーツ | 配置 | 内容 |
|-------|------|------|
| `←` 戻る | 左 | S-002 サインアップへ戻る（後述の警告ダイアログあり） |
| タイトル | 中央 | `メールを確認` |
| (右はアイコンなし) | 右 | - |

> 認証系画面のため BottomNavigation は非表示。

#### イントロブロック（ヘッダー直下）

- 大きめの見出し: `確認コードを入力`（h1相当、24px / 700）
- サブテキスト（複数行可）:
  - 1行目: `下記のメールアドレスに6桁のコードを送信しました。`
  - 2行目: `<user@example.com>`（送信先メールアドレス、`color/text-primary`、500、改行で目立たせる）
- メールアドレス右に小さく `変更` リンク（タップで S-002 へ戻る、後述の確認ダイアログあり）
- 下に余白24px

#### コード入力フィールド

横並び6マスのスタイル（実装は内部的に1つの input でも、見た目は6マス分割）：

```
┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐
│  │ │  │ │  │ │  │ │  │ │  │
└──┘ └──┘ └──┘ └──┘ └──┘ └──┘
```

| 項目 | 値 |
|------|-----|
| マスのサイズ | 48×56px（高さは Input 標準より少し縦長） |
| マス間の間隔 | 8px |
| フォント | 数字大きめ（24px / 600）、中央寄せ |
| 枠線 | 1px `color/border`、フォーカス時 2px `color/primary` |
| キーボード | `inputmode=numeric`、`autocomplete=one-time-code`、`pattern=[0-9]*` |
| 入力制約 | 半角数字のみ、1マス1文字、6文字で自動的に確認実行（後述） |

#### 再送・補助情報セクション（コード入力欄の下）

- `コードを再送`（リンク、`color/primary`、text/body）
  - 直後は60秒間タップ不可（後述）
  - 残り秒数があるときは `コードを再送（あと45秒）` のように表示、`color/text-secondary`
- `メールが届かない場合は、迷惑メールフォルダもご確認ください。`（text/caption、`color/text-secondary`）

#### ボトム固定フッター（72px / 共通仕様準拠）

- `確認` ボタン（Button `lg` primary、横幅100%、高さ48px）
  - 6桁が揃うまで非活性
  - タップでローディング状態へ（スピナー表示、入力ロック）

> **設計判断**: 6桁が揃った瞬間に自動で確認APIを叩く方式も検討したが、誤入力時の修正動線が複雑になるため、明示的に「確認」ボタンを押す形にした（ただし「Enterキー / 6桁入力完了で自動送信」をオプションで採用するかは未決事項として残す）。

### 🔄 インタラクション

#### コード入力のキー操作

- 1文字入力すると次のマスにフォーカスが自動で移動
- Backspace で空マスから戻る場合、前のマスにフォーカスが戻り、その文字を削除
- 6桁ペースト時：1つ目のマスにペーストすると6マスに順番に分配
  - 数字以外は無視、6桁を超えた分は捨てる
- iOS/Android の SMS / メールアプリからの「自動入力」候補に対応（`autocomplete=one-time-code`）

#### バリデーション

- 全マス埋まる → 「確認」ボタン活性化
- 数字以外の入力は弾く（IMEはオフ）
- 入力途中のエラー表示はしない（送信時にまとめて検証）

#### 確認APIの呼び出し

```
[確認] タップ
    ↓
Cognito SDK confirmSignUp({
  username: <email>,         // S-002 から state で引き継ぎ
  confirmationCode: <6桁>
})
    ↓
成功: ボタンスピナー → 短い成功表示 → S-004 へ自動遷移
失敗: エラーバナー表示、入力欄をクリア（後述のエラー別挙動を参照）
```

#### コード再送

- `コードを再送` リンクをタップ:
  ```
  Cognito SDK resendConfirmationCode({
    username: <email>
  })
  ```
- 成功時:
  - 上部にトースト `info` 「コードを再送しました」（3秒）
  - 再送リンクは60秒間カウントダウン非活性化（`コードを再送（あと60秒）`）
  - コード有効期限のカウントダウンもリセット（後述）
- 失敗時:
  - エラートースト `error` 「再送に失敗しました。しばらくしてからお試しください」
  - リンクは即座に再タップ可能

#### コード有効期限の表示

- 画面下部（フッターの上）に小さく表示: `コードの有効期限：あと 12:34`
- 60秒ごとに更新、残り1分を切ったら `color/danger` で強調
- 期限切れ後は `コードの有効期限が切れました。再送してください。` に切り替え + 確認ボタン非活性化

### 📡 データ・API

このページは **バックエンドAPIを呼ばず、Cognito SDKを直接呼び出す**。

```
Cognito SDK confirmSignUp({ username, confirmationCode })  // 確認時
Cognito SDK resendConfirmationCode({ username })           // 再送時
```

- `username` (= メールアドレス) は S-002 から **クライアントサイドの一時 state** で引き継ぐ
  - URLパラメータには載せない（メールアドレス漏洩を防ぐ + メール本文との一貫性）
  - state を持たずに直接 `/signup/verify` を開いた場合は S-002 へリダイレクト

### 🌀 状態

| 状態 | 表示 |
|------|------|
| `default` | 通常表示、コード未入力、確認ボタン非活性 |
| `entering` | コード入力中、6桁未満で確認ボタン非活性 |
| `ready` | 6桁入力完了、確認ボタン活性 |
| `submitting` | 確認ボタンスピナー、入力欄ロック、再送リンクも非活性 |
| `success` | 短い成功表示 → S-004 へ自動遷移 |
| `error` | エラーバナー or インラインエラー表示、コード欄をクリア（場合によって保持） |
| `expired` | コード有効期限切れ表示、確認ボタン非活性、再送を強調 |
| `locked` | 試行回数超過、確認ボタン非活性、再送リンクも一時停止 |

### ⚠️ エッジケース

#### Cognitoエラー

| エラーコード | 表示メッセージ | 動作 |
|-------------|--------------|------|
| `CodeMismatchException` | 「コードが正しくありません」 | インラインエラー、コード欄を赤枠 + クリア、フォーカスを先頭に戻す。試行回数カウンタを表示（後述） |
| `ExpiredCodeException` | 「コードの有効期限が切れました。再送してください」 | 上部エラーバナー、確認ボタン非活性、再送リンクを強調表示 |
| `NotAuthorizedException`（既に確認済み） | 「このアカウントは既に確認済みです」 | 上部 info バナー + `ログインへ` ボタンを併設して S-005 へ |
| `LimitExceededException` / `TooManyFailedAttemptsException` | 「試行回数が上限に達しました。しばらくしてからお試しください」 | `locked` 状態へ、確認ボタンと再送リンクを15分間非活性 |
| `UserNotFoundException` | 「ユーザーが見つかりません。サインアップからやり直してください」 | エラーバナー + `サインアップへ戻る` ボタン |
| `NetworkError` / その他 | 「確認に失敗しました。通信状況をご確認ください」 | 上部エラーバナー、再試行可、入力は保持 |

#### 残り試行回数の表示

- `CodeMismatchException` 発生時、エラーメッセージに残り回数を添える
  - 例: `コードが正しくありません（残り 2 回）`
- Cognito 側のロックアウト閾値（デフォルト5回）にあわせて、5回連続失敗で `locked` 状態へ
- 残り回数はクライアント側でカウント（Cognito からは直接返らない想定）。サーバ側の正確な状態と乖離する可能性があるため、UIは目安として表示する

#### コード期限切れ

- Cognito の検証コード有効期限は **24時間**（標準）。ただし UI 上は短めに `15分` のカウントダウンを表示し、切れたら自動的に再送を促す
  - 実際の Cognito 側期限とは別の UI 上のソフト期限という扱い
  - ハード期限（24時間）切れの場合は `ExpiredCodeException` で対応
- カウントダウンが切れたら：
  - 確認ボタン非活性
  - コード入力欄は薄く `disabled` 表示
  - 再送リンクを `color/primary` に強調

#### メールが届かない

- 「メールが届かない場合」のヘルプテキストを表示
- 主な原因として案内:
  - 迷惑メールフォルダの確認
  - メールアドレスの誤入力 → `変更` リンクから S-002 へ戻る
  - ドメイン受信設定（`@example.com` を許可）
- `コードを再送` を試してもらう（60秒制限あり）

#### 「変更」リンク（メールアドレスを直す）

- `変更` リンクタップで確認ダイアログ:
  - タイトル: 「メールアドレスを変更しますか？」
  - 本文: 「これまでに送信されたコードは無効になります」
  - ボタン: `キャンセル` / `変更する`
- 「変更する」で S-002 サインアップへ戻る
  - S-002 のフォームには直前のメールアドレスをプリセット（パスワードはセキュリティ上クリア）

#### 戻るボタン操作

- ヘッダー左 `←` タップ、またはOSの戻るジェスチャー
- 確認ダイアログ表示:
  - タイトル: 「登録を中断しますか？」
  - 本文: 「コードを入力すると登録が完了します。中断すると、後で再度サインアップが必要になる場合があります」
  - ボタン: `続ける`（キャンセル）/ `中断する`（破壊的、赤）
- 「中断する」で S-001 スプラッシュへ

> **設計判断メモ**: Cognito 上は「未確認ユーザー」として残るため、同じメールアドレスで再サインアップしようとすると `UsernameExistsException` になる。S-005 ログインで未確認エラーが返った場合の救済導線は別途整備が必要（未決事項に記載）。

#### オフライン時

- 確認・再送ともにタイムアウト → エラーバナー「オフラインです。接続後に再度お試しください」
- 入力中のコードは保持

#### 多重サブミット

- `submitting` 状態では確認ボタン・再送リンク・入力欄をすべて非活性
- ダブルタップでの二重リクエストを防ぐ

#### 既ログインユーザーが `/signup/verify` に直接アクセス

- ルートガードで判定し、ログイン済みなら `/home` へ自動リダイレクト
- state（メールアドレス）を持たないアクセスは S-002 へリダイレクト

### 💭 設計判断メモ

| 判断 | 理由 |
|------|------|
| 6マス分割UI | 「6桁である」ことが視覚的に伝わる、ペースト・自動入力にも対応しやすい |
| 6桁入力完了で自動確認はしない | 誤入力時の修正動線が悪くなる。明示的な「確認」ボタンで意図を確定 |
| メールアドレスは画面上に表示 | 「どのメールに送ったか」を見せることで誤アドレス発覚を早める |
| `変更` リンクを目立つ位置に | 誤ったメールアドレスで詰まるパターンを救済 |
| 再送に60秒クールダウン | スパム的な連打防止、Cognito 側のレート制限にも配慮 |
| UI上のソフト期限（15分） | Cognito の24時間期限は長すぎてユーザーが「まだ有効」と勘違いしやすい。15分で再送を促すことで、新しいコードを使ってもらう |
| 試行回数を表示 | 「あと何回失敗できるか」を見せ、慎重に入力してもらう |
| 中断時に警告ダイアログ | 入力途中で離脱すると、未確認ユーザーが残ってしまうため |
| state は URL に載せない | メールアドレスをURL/履歴/Refererに残さない |
| `autocomplete=one-time-code` 対応 | iOS/Android のメール本文からの自動補完を活用、入力ハードルを下げる |
| 認証系画面で BottomNavigation 非表示 | screens.md の共通仕様に準拠 |
