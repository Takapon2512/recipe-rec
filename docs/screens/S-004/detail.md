## S-004 MFA初期設定（QR表示）

**URL**: `/signup/mfa-setup`
**Figma**: [{TBD}]({TBD})

### 🎯 目的

- メール検証を終えたユーザーに、TOTP認証アプリ（Google Authenticator 等）を登録してもらい、MFAを有効化する
- 「認証アプリって何？」という初心者ユーザーにも、迷わず最後までやり切ってもらえる導線にする
- QRが読めない環境（PCブラウザ・カメラ不可端末等）でも、シークレットキーの手入力で代替できるようにする
- アカウントロックアウトを防ぐため、リカバリー手段（バックアップコード等）の保存を強く促す

#### ヘッダー（上部固定、56px / 共通仕様準拠）

- 3ステップの最終段階
- text/caption (12px)、`color/text-secondary`、現在地のみ `color/primary` で強調

#### 手順セクション

縦に番号付きの3ステップで案内：

##### ステップ1: 認証アプリをインストール

- 番号バッジ `1`（24×24px、`color/primary` 円背景、白文字）
- 本文: `Google Authenticator、Microsoft Authenticator、1Password などの認証アプリをスマートフォンにインストールしてください。`
- 下に小さく `対応アプリを見る` リンク → ヘルプボトムシートを開く

##### ステップ2: QRコードを読み取り

- 番号バッジ `2`
- 本文: `アプリで以下のQRコードを読み取ってください。`
- **QRコード表示**:
  - サイズ: 200×200px（中央寄せ）
  - 背景: 白、周囲に16pxの余白
  - 角丸 `radius/lg` (12px)、外側に薄いシャドウ
  - QRデータ: `otpauth://totp/{ServiceName}:{email}?secret={base32Secret}&issuer={ServiceName}&algorithm=SHA1&digits=6&period=30`
- QR下に `読み取れない場合` リンク（タップでシークレットキーの手入力エリアを展開、後述）

##### シークレットキー手入力エリア（折りたたみ式）

QRの下、初期は折りたたまれている。`読み取れない場合` タップで展開：

- セクションタイトル: `または手入力で登録`（h3、18px / 600）
- 説明: `お使いの認証アプリに、以下のキーを手入力してください。`
- シークレットキー表示:
  - 形式: `XXXX XXXX XXXX XXXX XXXX XXXX XXXX XXXX`（4文字ごとに半角スペース、Base32文字列）
  - 文字色: `color/text-primary`、フォントは等幅（モバイルでも読み間違いを減らす）
  - 背景: `color/background`、パディング12px、角丸 `radius/md`
- 右側に `コピー` アイコンボタン（タップでクリップボードにコピー、トースト `success` 「コピーしました」）

##### ステップ3: コードを入力

- 番号バッジ `3`
- 本文: `認証アプリに表示されている6桁のコードを入力してください。`

#### TOTPコード入力フィールド

S-003 と同じスタイルの6マス分割UI：

```
┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐
│  │ │  │ │  │ │  │ │  │ │  │
└──┘ └──┘ └──┘ └──┘ └──┘ └──┘
```

| 項目 | 値 |
|------|-----|
| マスのサイズ | 48×56px |
| マス間の間隔 | 8px |
| フォント | 24px / 600、中央寄せ |
| 枠線 | 1px `color/border`、フォーカス時 2px `color/primary` |
| キーボード | `inputmode=numeric`、`autocomplete=one-time-code`、`pattern=[0-9]*` |
| 入力制約 | 半角数字のみ、1マス1文字 |

> **設計判断**: S-003 と同じ6マスUIにすることで、ユーザーがすでに学んだ操作パターン（自動フォーカス移動・ペースト分配）をそのまま使える。

#### TOTPコードの残り有効時間表示

コード入力欄の下に小さく：

```
コードは30秒ごとに更新されます（あと 18秒）
```

- 30秒の周期に合わせてカウントダウン（クライアント側で時刻計算）
- 残り5秒を切ったら `color/danger` で点滅
- 5秒未満で確認ボタンを押すと、サーバ検証時に期限切れになるリスクがあるため、注意文を表示

#### 重要な注意事項ブロック

確認ボタンの上に、目立つカードで配置：

```
⚠️ 重要：認証アプリを失わないでください
スマホを紛失すると、ログインできなくなる場合があります。
複数端末への登録、またはシークレットキーの安全な保管を強くおすすめします。
```

- 背景: `color/warning` 薄系（`#FEF3C7`）
- アイコン: ⚠️（24px）
- パディング16px、角丸 `radius/md`
- text/body (16px)、`color/text-primary`

#### ボトム固定フッター（72px / 共通仕様準拠）

- `設定完了` ボタン（Button `lg` primary、横幅100%、高さ48px）
  - 6桁が揃うまで非活性
  - タップでローディング状態へ（スピナー表示、入力ロック）

### 🔄 インタラクション

#### 画面初期表示時の動作

```
画面マウント
    ↓
（S-003 ConfirmSignUp 成功後、S-003 で initiateAuth → MFA_SETUP チャレンジを受け取っている前提）
    ↓
Cognito SDK associateSoftwareToken({ session })
    ↓
SecretCode を取得 → QRコードに変換して表示、手入力用キーも生成
    ↓
レスポンスの session を state に保持（次の VerifySoftwareToken で使う）
```

- API呼び出し中はQRコード部分にスケルトン表示
- 失敗時はエラー画面 + 再試行ボタン（後述）

#### コード入力

- S-003 と同じ挙動：
  - 1文字入力で次のマスへ自動フォーカス
  - Backspace で前のマスに戻る
  - 6桁ペースト時に各マスに分配
  - 数字以外は無視

#### 設定完了APIの呼び出し

```
[設定完了] タップ
    ↓
Cognito SDK verifySoftwareToken({
  session,
  userCode: <6桁>,
  friendlyDeviceName: "<ServiceName> Web"  // 表示名
})
    ↓
成功:
  Cognito SDK respondToAuthChallenge({ ... MFA_SETUP の最終応答 ... })
    ↓
  JWT を取得
    ↓
  バックアップコード生成 / 表示画面へ（後述、設計判断メモ参照）
    ↓
  GET /api/me（JIT作成）
    ↓
  S-101 ホーム
失敗: エラーバナー表示、コード欄をクリア
```

> **設計判断メモ**: `verifySoftwareToken` → `respondToAuthChallenge` の流れは Cognito の SDK 仕様上、`MFA_SETUP` セッションを最後まで完了させる必要がある。失敗するとユーザーは「MFA未設定の確認済みユーザー」として宙に浮くため、エラーハンドリングは慎重に。

#### QRコードのコピー対策

- QRコード自体はスクリーンショットで保存できるが、推奨はしない
- 「QRコードを保存」ボタンは設けない（流出リスクを下げるため）
- ただし、シークレットキーの `コピー` は許可（ユーザー自身のパスワードマネージャー保存を妨げない方針）

#### ヘルプボトムシート

`?` アイコンタップで開く：

- タイトル: `認証アプリとは？`
- 内容:
  - 「30秒ごとに変わる6桁のコードを生成するスマホアプリです」
  - 「パスワードが漏れても、コードがないとログインできないため安全性が高まります」
- セクション: `対応アプリ`
  - Google Authenticator（iOS / Android）
  - Microsoft Authenticator（iOS / Android）

### 📡 データ・API

このページは **バックエンドAPIを呼ばず、Cognito SDKを直接呼び出す**。

```
Cognito SDK associateSoftwareToken({ session })          // 画面表示時
Cognito SDK verifySoftwareToken({ session, userCode })   // 設定完了時
Cognito SDK respondToAuthChallenge({ ... })              // MFA_SETUP 完了
```

- `session` は S-003 で受け取った MFA_SETUP チャレンジのものを state で引き継ぐ
- `verifySoftwareToken` 成功後の最終 `respondToAuthChallenge` で JWT を取得
- その後、初回の `GET /api/me` で JIT 方式によりバックエンド側に `users` レコードを作成（design.md §1.6 参照）

### 🌀 状態

| 状態 | 表示 |
|------|------|
| `loading_qr` | 画面マウント直後、QR領域にスケルトン、入力欄は disabled |
| `ready` | QR表示済み、コード入力待ち、設定完了ボタン非活性 |
| `entering` | コード入力中、6桁未満で設定完了ボタン非活性 |
| `ready_to_submit` | 6桁入力完了、設定完了ボタン活性 |
| `submitting` | 設定完了ボタンスピナー、入力欄ロック |
| `success` | 短い成功表示 → バックアップコード画面 or S-101 へ自動遷移 |
| `error` | エラーバナー表示、コード欄をクリア、再入力可 |
| `qr_load_error` | QR取得失敗、エラー表示 + 再試行ボタン |
| `locked` | 試行回数超過、設定完了ボタン非活性、サポート案内 |

### ⚠️ エッジケース

#### Cognitoエラー（verifySoftwareToken）

| エラーコード | 表示メッセージ | 動作 |
|-------------|--------------|------|
| `EnableSoftwareTokenMFAException` / `CodeMismatchException` | 「コードが正しくありません。アプリの最新コードで再度お試しください」 | インラインエラー、コード欄を赤枠 + クリア、フォーカス先頭。残り試行回数を併記 |
| `InvalidParameterException` | 「コードの形式が正しくありません」 | インラインエラー、コード欄クリア |
| `NotAuthorizedException`（session期限切れ） | 「セッションの有効期限が切れました。最初からやり直してください」 | エラーバナー + `ログインへ戻る` ボタン（S-005 へ） |
| `LimitExceededException` / `TooManyRequestsException` | 「試行回数が上限に達しました。しばらくしてからお試しください」 | `locked` 状態へ、設定完了ボタン非活性 |
| `NetworkError` / その他 | 「設定に失敗しました。通信状況をご確認ください」 | エラーバナー、再試行可、入力は保持 |

#### Cognitoエラー（associateSoftwareToken）

QR取得自体に失敗した場合：

- `qr_load_error` 状態へ
- 中央に: `QRコードの取得に失敗しました`
- `再試行` ボタン → associateSoftwareToken を再呼び出し
- 3回連続失敗の場合は `ログインからやり直す` 導線を表示

#### TOTPコードの時刻ズレ

スマホ端末の時刻設定がずれていると、生成されるコードがサーバ側で無効になる：

- 連続失敗時のエラーメッセージに追記: `スマートフォンの時刻設定が「自動」になっているかご確認ください`
- 連続3回失敗で、時刻設定の確認を促すバナーを表示

#### 残り試行回数の表示

- S-003 と同様、`CodeMismatchException` 発生時にクライアント側でカウント
  - 例: `コードが正しくありません（残り 2 回）`
- 5回連続失敗で `locked` 状態へ
- ロック時はサポート連絡先（または「ログインからやり直す」）を案内

#### コード入力中に30秒経過

- カウントダウンが0になった瞬間、入力済みのコードを赤枠ハイライトし、注意文表示: `コードが更新されました。最新のコードで入力してください`
- 入力欄を自動クリアはしない（ユーザーが意図的に古いコードを送信したい場合もあるため）
- 送信時にサーバ側で無効と判定された場合は通常のエラーフローで対応

#### 戻るボタン操作 / 中断

- ヘッダーには戻る矢印を表示しない
- OS の戻るジェスチャー、もしくはブラウザの戻る:
  - 確認ダイアログ表示:
    - タイトル: 「MFA設定を中断しますか？」
    - 本文: 「セキュリティ強化のため、MFAの設定は完了することを強くおすすめします。中断すると、後で再度ログインから設定が必要になります」
    - ボタン: `続ける`（キャンセル）/ `中断する`（破壊的、赤）
- 「中断する」で S-001 スプラッシュへ
  - Cognito 上は「メール確認済み・MFA未設定」のユーザーとして残る
  - 次回 S-005 ログイン時に再度 `MFA_SETUP` チャレンジが返り、S-004 にリダイレクトされる想定

#### バックアップコード/リカバリー手段

設計上の方針として、設定完了後にバックアップコード画面を挟むか、現時点では未決：

- **案A**: 設定完了後にバックアップコード（10個程度）を表示し、ダウンロード/コピーを促す
- **案B**: バックアップコードは出さず、シークレットキーを「安全に保管してください」と促すに留める（実装簡略化）
- **案C**: ヘルプセンター経由でアカウント復旧フローを別途整備

> 未決事項として残し、初期実装は案Bを採用予定。

#### Googleで登録したユーザーがこの画面に来ることはない

- design.md の方針通り、Google経路は MFA を Google 側に委譲
- ルートガードで `custom:provider == "google"` のユーザーがアクセスした場合は S-101 へリダイレクト

#### オフライン時

- QR 取得失敗 → `qr_load_error` 状態
- 設定完了APIタイムアウト → エラーバナー「オフラインです。接続後に再度お試しください」
- 入力中のコードは保持

#### 多重サブミット

- `submitting` 状態では設定完了ボタン・入力欄・QR下の各リンクをすべて非活性

#### 既ログインユーザーが `/signup/mfa-setup` に直接アクセス

- ルートガードで判定し、ログイン済み（かつMFA設定済み）なら `/home` へ自動リダイレクト
- session（MFA_SETUP チャレンジ）を持たないアクセスは S-005 へリダイレクト

### 💭 設計判断メモ

| 判断 | 理由 |
|------|------|
| 戻るボタンを出さない | 中途半端な状態（MFA未設定の確認済みユーザー）を生まないため、前進のみのフローにする |
| 3ステップで番号付き案内 | 「認証アプリ？QR？」と初心者がつまずきやすいので、手順を明示的に分割 |
| QRと手入力キーの両対応 | カメラ不可・PCブラウザ・ヘッドセット端末などQR読み取り不可ケースを救済 |
| シークレットキーは4文字ごとにスペース | 手入力時の読み間違い・打ち間違いを減らす |
| シークレットキーのコピー許可 | パスワードマネージャー利用を妨げない。ユーザー自身の安全な保管を尊重 |
| QR画像の保存ボタンは置かない | ローカルへの画像保存はスクリーンショット流出のリスクがあるため積極推奨しない |
| 6マスUIで S-003 と統一 | ユーザーが学習した操作パターンを再利用、認知負荷を下げる |
| 残り有効時間カウントダウン | 「あと何秒で変わる」が見えると、ユーザーが落ち着いて入力できる |
| 警告カードを目立たせる | アカウントロックアウト発生時のサポートコスト・ユーザー被害を予防 |
| 認証アプリ名を具体例で挙げる | 「認証アプリって何？」を解消する最短ルート |
| ヘルプは右上 `?` アイコンに集約 | 知っている人の動線を邪魔しない |
| `friendlyDeviceName` を設定 | Cognito 側の登録デバイス一覧で識別できるようにする（将来 S-602 等で表示） |
| Google ユーザーはこの画面に来ない | MFA は Google 側に委譲する方針（design.md §1.2）に準拠 |
| 初期実装ではバックアップコードを出さない | Cognito 標準機能ではバックアップコードは提供されない。実装する場合は自前生成・自前保存が必要で複雑度が増す |
| 認証系画面で BottomNavigation 非表示 | screens.md の共通仕様に準拠 |
