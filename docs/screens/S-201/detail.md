## S-201 在庫一覧

**URL**: `/inventory`
**Figma**: [{TBD}]({TBD})

### 🎯 目的
- いま家にある食材・日用品を一覧で確認する
- 賞味期限切れが近いものを把握する
- 「使い切った」「1個使った」を素早く記録する
- 検索・絞り込みで目的の在庫を見つける

### 📋 構成要素

#### ヘッダー（上部固定、約56px）
| パーツ | 配置 | 内容 |
|-------|------|------|
| タイトル | 左 | `在庫` |
| 検索アイコン | 右 | タップで検索バー展開 |
| ソートアイコン | 右 | タップでソートメニュー |

#### チップフィルタ（ヘッダー下、横スクロール）
- カテゴリ（野菜 / 肉 / 魚 / 乳製品 / 調味料 ...）
- 保管場所（冷蔵 / 冷凍 / 常温）
- **期限間近のみ**（トグル、特に重要）

複数選択可。選択中のチップは塗りつぶし表示。

#### 在庫リスト（メインコンテンツ）
**標準カード**（高さ約80px、2行構成）：

```
┌────────────────────────────────────┐
│ ●  鶏もも肉                         │
│    あと2日 / 300g · 冷蔵 · 肉      │
└────────────────────────────────────┘
```

| 要素 | 詳細 |
|------|------|
| ●（左ドット） | 期限なし=灰、期限〜3日=黄、期限切れ=赤 |
| 1行目（大） | 商品名（16px / 600） |
| 2行目（小） | 期限テキスト + 数量・単位 + 保管場所 + カテゴリ（13px / 400、`text-secondary` 色） |
| 期限テキスト | 期限間近=黄、期限切れ=赤、それ以外=`text-secondary` |

#### フローティングアクションボタン（FAB、右下）
- アイコン：`+`
- タップで `/inventory/new`（S-203）へ
- スクロール時も常時表示

#### ページネーション（リスト下部）
- `< 1 2 3 ... 5 >` シンプル形式
- 1ページあたり20件（API既定値）

### 🔄 インタラクション

#### スワイプ操作

| 方向 | アクション | API | フィードバック |
|------|----------|-----|--------------|
| ←（左） | 使い切った | `DELETE /api/inventory/{id}` | カードがリストから消える + トーストに **「取り消し」付き**（5秒） |
| →（右） | 1個使う | `PATCH /api/inventory/{id}` (quantity -= 1) | カード内の数量が即時更新（トーストなし） |

**スワイプ実装の詳細**：
- スワイプ閾値：カード幅の30%
- スワイプ中は背景色（左=赤、右=青）とアイコンが見える
- 閾値未満で離した場合はカードがバウンドして元に戻る
- アクション完了時のアニメーション：左スワイプはカードがフェードアウトして消える、右スワイプは数量数字が一瞬ハイライト

#### スワイプ取り消しの仕様
- トースト：「鶏もも肉を削除しました」「取り消し」ボタン付き
- 取り消し操作：論理削除フラグを戻す（`deleted_at = NULL` への復元 API）
- タイムアウト：5秒で自動消滅
- 連続して別のカードを削除した場合：直近のトーストは閉じ、新しいトーストに置き換わる（同時に複数表示しない）

#### タップ操作
- カード本体タップ → 詳細画面（S-202）へ
- 検索アイコンタップ → 検索バー展開（後述）
- ソートアイコンタップ → ソートメニュー（後述）

#### 検索バー
- 検索アイコンタップで上部にバーが下りてくる（高さ48px、150ms ease-out）
- バー表示中はチップフィルタが隠れる（高さの節約）
- 入力中は **300msデバウンス** でAPI呼び出し
- `×` ボタンで入力クリア、`キャンセル` ボタンでバーを閉じる

#### ソートメニュー
- アクションシート風（下から出現）
- 選択肢：
  1. **期限近い順**（既定）
  2. 追加日が新しい順
  3. 名前順（あいうえお）
  4. カテゴリ別グループ表示
- 選択中の項目にチェックマーク

#### プルダウンリフレッシュ
- リスト最上部からプルダウンでリロード
- スピナーは標準的なネイティブ風

#### 自動リフレッシュ
- 画面フォーカス時（タブ切替、画面復帰）に自動再取得
- TanStack Query の `refetchOnWindowFocus: true` 相当
- ローディング表示は控えめに（既存リストを残したまま、背景でリフレッシュ）

### 📡 データ・API

#### 一覧取得
```
GET /api/inventory?page=1&per_page=20&sort=expires_at&category_id=&storage_location=&q=
```

- 期限なしのレコードはレスポンスでは末尾に並ぶようサーバ側でソート
- レスポンス形式は `api.md` 参照

#### クイック更新
```
PATCH /api/inventory/{id}      # 1個使う：quantity -= 1
DELETE /api/inventory/{id}     # 使い切った：論理削除
```

#### 取り消し（復元）
取り消し操作専用エンドポイントは現状の `api.md` にないため、追加が必要：

```
POST /api/inventory/{id}/restore   # deleted_at を NULL に戻す
```

### 🌀 状態

| 状態 | 表示 |
|------|------|
| `loading`（初回） | スケルトンカード5枚 |
| `loading`（再取得） | 既存リスト維持、最上部に細いプログレスバー |
| `loaded` | 通常表示 |
| `empty` | イラスト + 「最初の在庫を登録しよう」+ FAB強調 |
| `error` | インラインエラーバナー + 自動リトライ（3回、指数バックオフ） |
| `error after retries` | 「読み込みに失敗しました」+ 手動リトライボタン |
| `offline` | オフラインバナー（上部固定） |

#### 空状態の詳細
- 中央配置のシンプルイラスト（冷蔵庫 or 籠）
- 「在庫がまだありません」（h2）
- 「最初の食材を登録してレシピ提案を受けよう」（caption）
- `+ 在庫を追加` 大きめプライマリボタン

#### エラーバナーの詳細
- リスト最上部にバナー表示
- メッセージ：「読み込みに失敗しました。再試行中...」
- 自動リトライ：1秒、2秒、4秒間隔の3回
- 全失敗後：バナーを「読み込みに失敗しました」に変更し、`再試行` ボタンを表示

### ⚠️ エッジケース

#### 期限切れの表示
- 左ドット：赤
- 期限テキスト：「3日前」のように **過去日数を表示**（赤色）
- 並び順は通常通り（期限近い順の中に自然に含まれる、最上部に来る）
- 特別なセクション分けは行わない（情報量を増やさない方針）

#### 期限なしの表示
- 左ドット：灰
- 期限テキスト：表示しない
- 並び順：リストの **最後にまとめて** 配置

#### 大量データ（100件超）
- ページネーションで対応
- 1ページ20件、ページ番号を `< 1 2 3 ... N >` 形式で表示
- ページ移動時はリスト最上部にスクロール

#### スワイプ操作の競合
- 同時に複数のカードをスワイプした場合：先にスワイプを完了したものから処理
- スワイプ中にAPIが失敗した場合：カードが元の位置にバウンドして戻り、エラートースト表示

#### 数量が小数の場合
- 「1個使う」スワイプ：整数なら `-1`、小数（300g等）なら **詳細編集を促す**（スワイプ無効 or 詳細遷移）
- 単位が `g` `ml` `kg` `l` の場合は1個使うスワイプを無効にする

> **TODO**：単位ごとのスワイプ可否ルールを `api.md` の単位定義と整合させる。

#### 数量0未満になりそうな場合
- 1個使うスワイプで残り1個 → スワイプ完了で「使い切った」扱いに自動昇格
- スワイプ確定時、確認なしで削除（取り消しトーストは表示）

#### オフライン時
- データ取得不可時：直前のキャッシュを表示 + オフラインバナー
- スワイプ操作：楽観的更新でUIだけ反映、再接続時に同期。失敗時はロールバック + トースト

### 💭 設計判断メモ

| 判断 | 理由 |
|------|------|
| カードを2行（80px）構成にした | 期限テキストを大きく見せる方針と整合。1行だと情報過多 |
| 左ドット方式を採用 | バッジ表示よりノイズが少なく、複数並んでも圧迫感がない |
| スワイプを左右で別アクションに | 慣れたユーザーには最速。誤操作リスクは取り消し機能で緩和 |
| 「使い切った」のみ取り消し付き | 破壊的操作（再追加が手間）と非破壊的操作（数量1戻すだけ）で扱いを分ける |
| 期限切れも同じリストに含める | 緊急度を強調しすぎると緊張感が強い。色での連続的な表現で十分 |
| 期限なしを最後にまとめる | 期限管理アプリの世界観として「期限のあるもの」を優先表示 |
| ページネーション採用 | 個人利用で多くても100件程度。シンプルで実装も楽 |
| 検索アイコン展開方式 | 縦スペースの節約。100件超えのときに検索の価値が出る |
| 自動リトライ3回 | 一時的なネットワーク不調を吸収、ユーザーが何もせずに回復 |
