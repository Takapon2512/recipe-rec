## S-101 ホーム / ダッシュボード

**URL**: `/home`
**Figma**: [{TBD}]({TBD})

### 🎯 目的
- 起動直後に「いま何をすべきか」を一目で把握する
- 期限切れ間近の食材を見逃さない
- レシピ提案機能への自然な導線を提供する
- 今週の献立計画の状況を俯瞰する
- よく使う操作（在庫・献立追加）を素早く起動する

### 📋 構成要素

#### ヘッダー(上部固定、56px / 共通仕様準拠)
| パーツ | 配置 | 内容 |
|-------|------|------|
| 挨拶 + 名前 | 左 | 「おはよう、たろうさん」など、時間帯で変化 |
| 設定アイコン | 右 | タップで `/settings`(S-601)へ |

挨拶のロジック:
- 5:00〜10:59 → 「おはよう、{display_name}さん」
- 11:00〜17:59 → 「こんにちは、{display_name}さん」
- 18:00〜4:59 → 「こんばんは、{display_name}さん」
- `display_name` 未設定時は名前部分を省略(「おはよう」のみ)

#### 1. 期限間近セクション(最上部)

**通常時(期限間近あり)**:
- セクションヘッダー: `期限が近い在庫` + 件数バッジ(例: `5件`)
- 在庫カード3件(S-201と同じ標準カードを流用)
- 末尾に `もっと見る →` リンク → S-205 へ
- 「もっと見る」は4件以上のときだけ表示

**期限間近なし**:
- セクションを **コンパクトに**: 「✓ 期限間近の在庫はありません」
- 緑のチェックアイコン + 1行メッセージのみ(高さ約56px)

**初回(在庫0件)**:
- セクションを「在庫を登録すると、期限管理ができます」と空状態表示
- 中央に小さなイラスト + `+ 在庫を追加` ボタン

#### 2. レシピ提案CTAセクション

**通常時(在庫3件以上)**:
大きめプライマリボタン(高さ約88px、塗りつぶし):

```
┌──────────────────────────────────────┐
│ 🍳  おすすめレシピを見る              │
│     在庫12件 · うち2件が期限間近      │
└──────────────────────────────────────┘
```

- メイン文字(h2、白): `おすすめレシピを見る`
- サブ文字(caption、白80%透過): 在庫件数と期限間近の文脈
- 期限間近が0件のときは「在庫12件で作れるレシピ」のような表現
- タップで S-401 へ(期限間近があれば `prefer_expiring=true` をプリセット)

**在庫3件未満**:
- ボタンを **非活性 or 案内表示**: 「在庫を3つ以上登録すると、レシピを提案できます」
- ボタンを薄いグレーで、タップしても S-203 へ誘導

#### 3. 今週の献立セクション

セクションヘッダー: `今週の献立`(h2)+ `カレンダー →`(S-501へのリンク)

横並び7日ミニカレンダー:

```
月   火   水   木   金   土   日
●    ●    ◯    ●    ―    ―    ―
                今日
```

- 各日のセル幅: 画面幅 / 7
- 日付(数字)+ 曜日(小)
- ドット表示:
  - `●`(プライマリ色塗り): 献立あり
  - `◯`(プライマリ色枠のみ): 今日(献立有無問わず常にハイライト)
  - `―`(灰色): 献立なし
- セルタップで S-502(その日の献立詳細)へ

#### 4. クイックアクションセクション

セクションヘッダーなし(最下部、シンプル)

2つのカードボタンを横並び:

```
┌─────────────┐  ┌─────────────┐
│   📦         │  │   📅         │
│   在庫を追加  │  │   献立を追加  │
└─────────────┘  └─────────────┘
```

- カード型、各幅50%、高さ約88px
- アイコン(24px)+ ラベル
- タップで S-203 / S-503 へ

#### BottomNavigation
- 「ホーム」タブが選択中(背景色 or アイコン色で表現)
- 詳細は screens.md の共通仕様参照

### 🔄 インタラクション

#### プルダウンリフレッシュ
- ページ最上部からプルダウンで全データ再取得
- 期限間近 / 今週の献立 / ホーム表示用の在庫件数 を一括取得

#### 自動リフレッシュ
- 画面フォーカス時(タブ切替、画面復帰)に自動再取得
- S-201 と同じ仕様(TanStack Query の `refetchOnWindowFocus`)
- データ変更(他画面で在庫追加・献立変更)後の戻り表示が常に最新

#### セクション内のタップ動線

| タップ位置 | 遷移先 |
|-----------|-------|
| 期限間近の在庫カード | S-202 在庫詳細 |
| 期限間近「もっと見る」 | S-205 期限切れ間近一覧 |
| 「期限間近なし」状態の領域 | (遷移なし、表示のみ) |
| レシピ提案CTAボタン | S-401 提案条件入力(期限間近ありなら `prefer_expiring=true` をプリセット) |
| 今週の献立「カレンダー →」 | S-501 月ビュー |
| 今週の献立 各日セル | S-502 該当日の献立詳細 |
| クイックアクション「在庫を追加」 | S-203 在庫追加 |
| クイックアクション「献立を追加」 | S-503 献立追加(日付=今日でプリセット) |
| 設定アイコン | S-601 設定トップ |

#### 期限間近セクションのカード操作
- スワイプ操作は **無効**(ホームでは閲覧のみ、操作は S-201 / S-202 で行う)
- タップは詳細画面(S-202)へ
- 数量更新や削除はホームではできない、という割り切り

### 📡 データ・API

ホーム表示時に並列で以下を呼び出す:

```
GET /api/me                                    # ユーザー情報(display_name用、JIT作成も兼ねる)
GET /api/inventory/expiring?within_days=3      # 期限間近(最大3件をレスポンスから抽出)
GET /api/inventory?per_page=1                  # 在庫件数のみ取得(pagination.totalを使う)
GET /api/meal-plans?from={today}&to={today+6}  # 今週の献立
```

#### 件数取得の最適化(将来検討)
- 在庫件数だけ取得する専用エンドポイント `GET /api/inventory/summary` を切るか検討
- 現状は `per_page=1` で1件だけ取得して `pagination.total` を見る形

### 🌀 状態

| 状態 | 表示 |
|------|------|
| `loading`(初回) | ヘッダーは即表示、各セクションごとにスケルトン |
| `loading`(再取得) | 既存表示維持、上部に細いプログレスバー |
| `loaded` | 通常表示 |
| `empty`(在庫0件) | 各セクション空状態、CTA強調 |
| `error` | セクションごとに個別エラー表示 + 再試行 |
| `offline` | オフラインバナー(上部固定) |

#### セクション単位のエラー処理
- 4つのAPIは並列呼び出し、**1つ失敗しても他は表示する**
- 失敗したセクションだけ「読み込みに失敗しました(再試行)」を表示
- 全API失敗時のみ全画面エラー表示

### ⚠️ エッジケース

#### 在庫0件
- 期限間近セクション: 「在庫を登録すると、期限管理ができます」+ 在庫追加CTA
- レシピ提案CTA: 非活性 +「在庫を3つ以上登録すると、レシピを提案できます」
- 今週の献立: 通常通り表示(献立は在庫と独立)
- クイックアクション: 通常通り

#### 在庫1〜2件
- 期限間近セクション: 通常動作(該当があれば表示、なければコンパクト表示)
- レシピ提案CTA: 非活性のまま、「あと{N}件で提案できるようになります」
- それ以外は通常通り

#### 今週の献立が0件(全日なし)
- ミニカレンダー: すべて `―` 表示
- 「今週の献立を立ててみよう」と小さなコールアウト or `+献立を追加` CTAを下に

#### 今週が月またぎ
- 月曜始まりで7日表示、月をまたぐ場合は両月の数字を併記しても自然な流れ
- 例: `30 31 1 2 3 4 5`(10月末→11月頭)

#### 挨拶の境界時刻
- 4:59:59 までは「こんばんは」、5:00:00 から「おはよう」
- 画面表示時の時刻で判定、深夜0時にホームを開いても「こんばんは」

#### display_name 未設定 / 空文字
- 「おはよう」「こんにちは」「こんばんは」のみ表示
- 名前部分は完全に省略(「おはよう、さん」とはしない)

#### オフライン時
- キャッシュデータを表示(最後にホームを開いたときの内容)
- オフラインバナー上部固定
- リフレッシュ操作はエラートースト

#### 画面の縦スクロール量
- 期限間近3件 + 提案CTA + 今週の献立 + クイックアクション
- モバイル375pxで合計約 **600〜700px** の縦長
- iPhone 13 (画面高 844px) の場合、コンテンツ領域は `844 - 56(ヘッダー) - 64(BottomNav) - 34(SafeArea)` = **約690px**
- 1画面に全部入らないが、スクロール1回程度で全把握できる量

### 💭 設計判断メモ

| 判断 | 理由 |
|------|------|
| ダッシュボード型 | 在庫管理 × 献立 × LLM提案の3軸サービスとして全機能の入り口を見せる |
| コンテンツ順序: 期限間近→提案→献立→アクション | 「期限間近を見せた直後に提案CTA」でストーリー性を持たせる |
| 期限間近3件表示 | 3件は一目で把握できる量、それ以上は「もっと見る」へ |
| 期限間近なしは緑チェックの控えめ表示 | 「何もない」を肯定的に見せ、画面を圧迫しない |
| 提案CTAに在庫件数 + 期限間近を表記 | 「自分のために提案してくれてる感」を演出、行動喚起を強化 |
| 在庫3件未満は提案CTA非活性 | LLM呼び出しのコストを節約、提案精度も担保 |
| 今週の横並び7日ミニカレンダー | 一覧性が高く、空いている日が一目で分かる |
| クイックアクション2つに絞る | 在庫追加と献立追加が最頻、シンプルさ優先 |
| 時間帯による挨拶切り替え | 温かみとパーソナライズ感、毎回の起動が少し嬉しい |
| ホームではスワイプ操作なし | 閲覧画面と割り切り、操作は S-201/S-202 で行う |
| プルダウン + フォーカス自動再取得 | S-201と統一、ユーザーが学習した操作が他画面でも通用 |
| セクション単位のエラー処理 | 並列API取得で部分的成功を許容、UXを劣化させない |
| 初回も同じレイアウト | 「いつもと違う画面」感をなくし、操作を学びながら埋める |
