## S-002 サインアップ

**URL**: `/signup`
**Figma**: [{TBD}]({TBD})

### 🎯 目的

- 未ログインユーザーに、最短ルートでアカウントを作成してもらう
- 「メール+パスワード」と「Google」の2経路を1画面で提示し、好きな方を選べる設計にする
- 入力ハードルを下げつつ、パスワードポリシーや規約同意などの必須要件は明確に提示する

### 📋 構成要素

#### ヘッダー（上部固定、56px / 共通仕様準拠）

| パーツ | 配置 | 内容 |
|-------|------|------|
| `←` 戻る | 左 | S-001 スプラッシュへ戻る |
| タイトル | 中央 | `新規登録` |
| (右はアイコンなし) | 右 | - |

> 認証系画面のため BottomNavigation は非表示。

#### イントロブロック（ヘッダー直下）

- 大きめの見出し: `アカウントを作成`（h1相当、24px / 700）
- サブテキスト: `メールアドレスまたはGoogleアカウントで登録できます`（text/body、`color/text-secondary`）
- 下に余白24px

#### Googleで登録ブロック

- ボタン1つ：`Googleで登録`（Button `lg`、横幅100%、白背景 + 1px border、左にGoogleロゴ20px）
- タップで Cognito Hosted UI（Google IDプロバイダ指定）へリダイレクト
- 認証後は S-005 ログインのGoogleフロー終端と同じく、`/api/me` 経由で S-101 へ

#### 区切り

- 横線 + 中央に「または」（text/caption、`color/text-secondary`、線の色 `color/border`）
- 上下に余白16px

#### フォーム本体（縦スクロール）

##### 入力フィールド

| フィールド | 入力UI | 仕様 |
|-----------|-------|------|
| メールアドレス ※ | Input `text`（type=email） | 1〜254文字、メール形式、`autocomplete=email`、`inputmode=email` |
| パスワード ※ | Input `text`（type=password、目アイコンで表示切替） | 8文字以上、英大文字・小文字・数字・記号を含む、`autocomplete=new-password` |
| パスワード（確認用） ※ | Input `text`（type=password、目アイコンで表示切替） | 上のパスワードと完全一致、`autocomplete=new-password` |

##### パスワード強度・要件チェックリスト

パスワード入力欄の直下にリアルタイムで要件を可視化：

```
□ 8文字以上
□ 英大文字を含む
□ 英小文字を含む
□ 数字を含む
□ 記号を含む
```

- 入力に応じて満たした要件は `✓`（`color/success`）に切り替わる
- すべて満たすまで「登録」ボタンは非活性
- フォント: text/caption (14px)

##### 規約同意セクション

- チェックボックス（24×24px、タップ領域44×44px）
- ラベル: `[利用規約] と [プライバシーポリシー] に同意します`
  - `[利用規約]` / `[プライバシーポリシー]` はリンク（`color/primary`、下線）
  - タップで別画面 or ボトムシートで規約を表示（実装はモーダルで簡略化可）
- 未チェックでは「登録」ボタンは非活性

#### ボトム固定フッター（72px / 共通仕様準拠）

フォーム画面のため、BottomNavigation の代わりにボトム固定フッターを配置。

- `登録` ボタン（Button `lg` primary、横幅100%、高さ48px）
  - すべてのバリデーションを満たすまで非活性
  - タップでローディング状態へ（スピナー表示、入力ロック）

#### フッター直下

- 補助リンク: `すでにアカウントをお持ちの方は ログイン`
  - 「ログイン」部分が `color/primary` のリンク、タップで S-005 へ
  - text/body (16px)、中央寄せ

### 🔄 インタラクション

#### バリデーションのタイミング

S-203 と同じ方針：

- **初回フォーカス前はエラー表示しない**（入力前に赤くしない配慮）
- 一度フォーカスを離れた（blur）以降からインラインバリデーション開始
- パスワード要件チェックリストだけは例外で、入力開始と同時にリアルタイム更新

#### バリデーションルール

| 項目 | ルール | エラーメッセージ例 |
|------|--------|------------------|
| メールアドレス | RFC準拠メール形式、1〜254文字 | 「メールアドレスの形式が正しくありません」 |
| パスワード | 8文字以上、英大小・数字・記号を含む | 「パスワードは8文字以上で、英大小・数字・記号を含めてください」 |
| パスワード確認 | 上のパスワードと一致 | 「パスワードが一致しません」 |
| 規約同意 | チェック必須 | （未チェックではボタン非活性、エラー表示なし） |

#### パスワード表示切替

- 各パスワード欄の右端に目アイコン（24×24px）
- タップで `type=password` ↔ `type=text` を切替
- 確認用パスワードも独立して切替可能（互いに連動しない）

#### Googleで登録のフロー

```
[Googleで登録] タップ
    ↓
Cognito Hosted UI へリダイレクト（identity_provider=Google）
    ↓
Google ログイン・同意画面
    ↓
Cognito 側でJIT作成（初回時）
    ↓
コールバックURL（/auth/callback）に戻る
    ↓
GET /api/me（バックエンドで users レコードJIT作成）
    ↓
S-101 ホーム
```

- メール認証経路と異なり、**MFA設定（S-004）はスキップ**（Google側にMFAを委譲）
- 既に同じメールアドレスでメール認証アカウントが存在する場合は、Cognito側で紐付け済みのはず（設計判断: linking 設定を有効化する前提）

#### メール認証経路の遷移

```
[登録] タップ
    ↓
Cognito SDK signUp() 呼び出し
    ↓
成功: S-003 メール検証コード入力 へ遷移（メールアドレスを state で引き継ぎ）
    ↓
失敗: 上部にエラーバナー表示（後述）
```

### 📡 データ・API

このページは **バックエンドAPIを呼ばず、Cognito SDKを直接呼び出す**。

```
Cognito SDK signUp({
  username: <email>,
  password: <password>,
  userAttributes: [
    { Name: "email", Value: <email> },
    { Name: "custom:provider", Value: "cognito" }
  ]
})
```

- 認証情報（クライアントID等）はフロントエンドの環境変数から取得
- バックエンド `/api/me` の呼び出しは **MFA設定完了後・初回ログイン時** に行われる（design.md の JIT 方式に準拠）

#### Googleで登録の場合

- 直接APIは叩かず、Cognito Hosted UI へのリダイレクトのみ
- リダイレクトURL: `{Cognito Domain}/oauth2/authorize?identity_provider=Google&...`

### 🌀 状態

| 状態 | 表示 |
|------|------|
| `default` | 通常フォーム、登録ボタン非活性 |
| `valid` | 全バリデーション通過、登録ボタン活性 |
| `submitting` | 登録ボタンにスピナー、フォーム入力ロック、Googleボタンも非活性 |
| `success` | （遷移するため UI上は表示しない、即 S-003 へ） |
| `error` | 上部エラーバナー表示、フォームは保持、再送信可能 |

### ⚠️ エッジケース

#### 入力エラーの表示

- エラー項目の **直下に赤字メッセージ**（12px / `color/danger`）
- 該当項目の枠線も赤に変わる
- 登録ボタンはエラー解消まで非活性

#### Cognitoエラー

| エラーコード | 表示メッセージ | 動作 |
|-------------|--------------|------|
| `UsernameExistsException` | 「このメールアドレスは既に登録されています。ログインしてください」 | エラーバナー表示 + ログインリンクを目立たせる |
| `InvalidPasswordException` | 「パスワードがポリシーを満たしていません」 | パスワード欄にインラインエラー |
| `InvalidParameterException` | 「入力内容に誤りがあります」 | 上部エラーバナー |
| `TooManyRequestsException` | 「しばらく時間をおいて再度お試しください」 | 上部エラーバナー、ボタン10秒非活性 |
| `NetworkError` / その他 | 「登録に失敗しました。通信状況をご確認ください」 | 上部エラーバナー、再試行可 |

#### 既存メールアドレスでの登録試行

- `UsernameExistsException` を捕捉
- エラーバナーに加え、`ログインへ` ボタンを併設してログインへの導線を強化
- パスワードリセットへのリンクも添える（誤って二重登録しようとしているケースのフォロー）

#### パスワード貼り付け

- パスワードフィールドへの貼り付けは **許可**（パスワードマネージャー利用を妨げない）
- 「パスワードのコピー禁止」のような無意味な制限はかけない

#### パスワード自動入力

- `autocomplete=new-password` 指定でブラウザのパスワードマネージャー連携を促進
- 確認用パスワードも同じ `autocomplete=new-password` を指定

#### Googleで登録時に途中キャンセル

- Cognito Hosted UI 上で「キャンセル」or 戻るブラウザ操作 → 元の S-002 に戻る
- フォーム入力内容は保持されない（リダイレクト跨ぎのため）
- エラーメッセージは表示しない（ユーザー意図のキャンセルのため）

#### 入力済みで戻るボタンを押した場合

- ヘッダー左 `←` タップ、またはOSの戻るジェスチャー
- 入力内容の判定：
  - すべての入力が空 → 警告なしで S-001 へ戻る
  - 何か入力済み → 確認ダイアログ表示
    - タイトル: 「入力中の内容が破棄されます」
    - 本文: 「登録をやめて戻りますか？」
    - ボタン: `戻る`（キャンセル）/ `破棄して戻る`（破壊的、赤）

#### オフライン時

- Cognito SDK 呼び出しはタイムアウト → エラーバナー「オフラインです。接続後に再度お試しください」
- フォーム入力は保持

#### 多重サブミット

- `submitting` 状態では登録ボタンを非活性 + スピナー表示
- フォーム要素全体も `disabled` にする
- ダブルタップでの二重リクエストを防ぐ

#### 既ログインユーザーが `/signup` に直接アクセス

- ルートガードで判定し、ログイン済みなら `/home` へ自動リダイレクト
- S-001 と同じ挙動（design.md / screens.md S-001 の方針に準拠）

### 💭 設計判断メモ

| 判断 | 理由 |
|------|------|
| Cognito SDK を直接呼ぶ（API経由でない） | Cognito の責務範囲なので EC2 を経由する意味がない。バックエンド負荷も避けられる |
| Googleボタンを最上部に配置 | 多くのユーザーが Google アカウントを持つ前提で、最短経路を上に置く |
| メール経路とGoogle経路を1画面に集約 | ユーザーが選択肢を把握しやすい。経路ごとに画面を分けるよりシンプル |
| パスワード要件をリアルタイム可視化 | 「何を満たせばいいか分からない」を解消、入力中に学べる |
| パスワード確認欄を残す | 入力ミスを防ぐ。`new-password` の自動入力との両立も可能 |
| 確認用も独立して表示切替 | 一括切替より誤操作が少ない |
| 規約同意は必須 | 法的要件。「登録」=「同意」より明示同意の方が安全 |
| 規約リンクは別画面/ボトムシート | 同じ画面内で展開するとフォームから注意が逸れる |
| 既存メールエラー時にログイン導線を強化 | 二重登録しかけているユーザーを救う |
| MFA設定はメール経路のみ必須 | design.md の方針に準拠。Google経路は Google 側に委譲 |
| 初回フォーカス前のエラー非表示 | S-203 と統一、ユーザー体験を揃える |
