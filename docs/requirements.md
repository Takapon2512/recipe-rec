# 家庭用 在庫管理・献立支援システム 要件定義書

## 1. 概要

### 1.1 目的
家庭における食材・日用品の在庫を可視化し、献立計画とレシピ提案までを一気通貫で支援するWebアプリケーション。「冷蔵庫に何があるか分からない」「今日何を作ろうか迷う」といった日常の課題を解消することを目的とする。

### 1.2 対象ユーザー
- 個人利用（1〜数人）
- 家庭内での食材・日用品管理を行うユーザー

### 1.3 プラットフォーム
- Webアプリケーション（PC・スマートフォンブラウザ対応のレスポンシブデザイン）

---

## 2. 機能要件

### 2.1 認証機能

| 項目 | 内容 |
|------|------|
| 認証基盤 | AWS Cognito |
| 認証方式 | メールアドレス + パスワード認証 |
| 多要素認証(MFA) | 必須（TOTP方式：Google Authenticator等のアプリ） |
| ソーシャルログイン | Google認証（OAuth 2.0 / OIDC） |
| セッション管理 | JWTトークン（アクセストークン・リフレッシュトークン） |
| パスワードポリシー | 最低8文字、英大文字・小文字・数字・記号を含む |

#### 認証フロー
1. 初回登録：メールアドレス登録 → 確認コード入力 → MFA設定
2. ログイン：認証情報入力 → MFAコード入力 → ログイン完了
3. Googleログイン：Googleアカウント連携でログイン可能（MFAはGoogle側に委譲）

### 2.2 カレンダー機能（献立・料理計画）

#### 主な機能
- 日付ごとの献立登録（朝食・昼食・夕食・間食）
- 月間・週間・日次ビューの切り替え
- レシピとの紐付け（後述のLLM提案レシピを直接登録可能）
- 献立コピー機能（前週・前月の献立を複製）
- メモ欄（来客予定・外食予定など）

#### データ項目
- 日付、食事区分、料理名、レシピID（任意）、メモ、作成・更新日時

### 2.3 LLMによるレシピ提案機能

#### 概要
登録された在庫情報をもとに、現在の在庫から作成可能なレシピをLLMが提案する。

#### 機能詳細
- **提案トリガー**：ユーザーが「おすすめを見る」ボタンを押下、またはカレンダーの日付から呼び出し
- **入力情報**：現在の在庫リスト（食材名・数量・賞味期限）
- **出力情報**：
  - レシピ名
  - 必要な材料と分量（在庫からの使用量を明示）
  - 調理手順
  - 推定調理時間
  - 不足している材料（買い物リスト候補）
- **絞り込み条件（オプション）**：
  - 調理時間（〜30分など）
  - ジャンル（和・洋・中など）
  - 賞味期限が近い食材を優先使用するモード

#### 非機能
- レスポンス時間：30秒以内を目標
- 提案件数：1リクエストあたり3〜5件

### 2.4 在庫登録・管理機能

#### 入力方式
- 手入力のみ（バーコード・画像認識は本リリースのスコープ外）

#### データ項目
| 項目 | 必須 | 備考 |
|------|------|------|
| 商品名 | ○ | テキスト入力 |
| カテゴリ | ○ | 食材／調味料／日用品 等の選択式 |
| 数量 | ○ | 数値 |
| 単位 | ○ | 個・g・ml 等から選択 |
| 購入日 | △ | 任意 |
| 賞味期限／消費期限 | △ | 任意（カレンダー連携） |
| 保管場所 | △ | 冷蔵・冷凍・常温 等 |
| メモ | △ | 自由記述 |

#### 操作機能
- 一覧表示（カテゴリ・期限・名前でソート／フィルタ）
- 検索機能
- 数量の増減（+/−ボタンでクイック更新）
- 賞味期限が近い／切れた商品のアラート表示
- 一括削除・編集

## 3. 非機能要件

### 3.1 性能
- 通常画面の表示：2秒以内
- LLM応答：30秒以内

### 3.2 セキュリティ
- 通信：HTTPS（TLS 1.2以上）必須
- パスワード：ハッシュ化保存（Cognito標準）
- 個人データの暗号化保存
- 不正アクセス対策：レートリミット、ログイン試行回数制限

### 3.3 可用性
- 稼働率：99%以上を目標（個人利用想定のためベストエフォート）

### 3.4 ユーザビリティ
- スマートフォンでの片手操作を想定したUI
- 主要操作は3タップ以内で完了

## 4. システム構成（想定）

### 4.1 アーキテクチャ概要
```
[ブラウザ]
   ↓ HTTPS
[Vercel] (Next.js 配信・SSR/SSG)
   ↓ HTTPS (CORS)
[ALB / Nginx] (HTTPS終端)
   ↓
[EC2] (バックエンドAPI)
   ↓
[Amazon Cognito] (認証・MFA・Google OIDC)
[Amazon RDS for MySQL 8.0] (データ永続化)
[Amazon Bedrock] (Claude によるレシピ提案)
```

### 4.2 主要技術スタック
| レイヤー | 採用技術 |
|---------|---------|
| フロントエンド | Next.js + TypeScript |
| フロント配信 | Vercel（Hobbyプラン） |
| バックエンド | EC2 (t4g.nano / ARM) 上に Node.js または Python のAPIサーバ |
| HTTPS終端 | ALB + ACM、または EC2 上の Nginx/Caddy + Let's Encrypt |
| 認証 | Amazon Cognito User Pool |
| DB | Amazon RDS for MySQL 8.0 (db.t4g.micro / Single-AZ) |
| LLM | Amazon Bedrock（Claude） |
| IaC | Terraform または AWS CDK（任意） |

### 4.3 月額コスト試算（東京リージョン目安）
| 項目 | 構成 | 月額目安 |
|------|------|---------|
| Vercel | Hobby プラン | $0 |
| EC2 | t4g.nano | $3〜4 |
| RDS for MySQL | db.t4g.micro + gp3 20GB | $16〜18 |
| Cognito | MAU 50人未満 | $0 |
| Bedrock (Claude) | 軽い使用 | $1〜10 |
| **合計** | ALBを省略しEC2上のNginx/Caddyで代替する場合 | **約 $20〜35/月** |

※ ALB を採用する場合は別途 +$20/月 程度。
